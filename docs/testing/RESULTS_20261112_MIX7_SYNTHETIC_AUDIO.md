# MIX7: PTT と Mac 合成音声の試験（2026-11-12 JST）

## 範囲と完了条件

テスト環境②（Android 14/15/16/17、iOS Simulator、実機 iPhone、OPPO A79 5G）で最新のローカル候補を確認する。各送信元の PTT 押下中に受信側が `BUSY_REMOTE`、離した後に全端末が `READY` に戻ること、Mac の合成音声が実マイクから送信され相手端末で実際に再生されることを確認する。期限は 2026-11-12 06:00 JST または Codex 週次枠残量 3% 以下。実音声、端末識別子、診断原本は公開しない。

## ビルドと構成

- Android: ローカル候補 `1.0.23-ui23 (24)`。iOS: ローカル開発/Simulator候補 `1.0 (2026111135)`。いずれも公開配布済みとは扱わない。候補の経緯は [前回の MIX8 記録](RESULTS_20261111_CONSOLE_REFINEMENT_MIX8.md) / #88 / PR #90。
- Android 14、15、16 と iOS Simulator、実機 iPhone、OPPO の **6端末**を同時接続して実行。Android 17 は起動・インストールできたが利用登録画面で、登録なしのまま試験から除外。したがって MIX7 全7台の完了判定は保留。
- Mac の合成音声は私有の 48 kHz、単声道、8.505 秒の試験フィクスチャ。OPPO 本体スピーカーが通信出力先、Bluetooth Headset 接続端末なしを OS 音声状態で確認。Mac 内蔵スピーカーから OPPO 実マイクへ音響入力した。Mac の出力音量は試験前後とも 13、ミュートなし。

## 結果

| 試験 | 結果 | 観測 |
| --- | --- | --- |
| 6端末それぞれを送信元とする PTT 操作 | 6/6 成功 | 押下中、残る5端末は `BUSY_REMOTE`。離した後、6端末すべて `READY`。 |
| Mac 合成音声 → OPPO 実マイク → 受信側 | **再生失敗** | ユーザーの聴感では iPhone 実機、Android シミュレーターとも音声が再生されなかった。OPPO の `TX IN` は一回目 −54.4 dBFS、Android 15 の `RX` は別の再試験で −19.2 dBFS、`BUSY_REMOTE` と終了後 `READY` は観測した。メーター値だけでは可聴再生を証明しない。 |
| Android Emulator gRPC 合成音声注入 | 測定器の失敗 | 注入 API は終了したが、送信中の Android 15 `TX IN` は −96 dBFS。別回の受信サンプルも約10万にとどまり有効な音声照合にならなかった。製品の音声失敗と判定しない。#59 の既知の試験基盤問題と整合。 |

`BUSY_REMOTE` と音量メーターは制御状態・アプリ内信号の観測に限る。iPhone と Android シミュレーターの両方で可聴再生がなかったとの報告があり、インカム機能の合格判定は不可。追加再試験では同じ送信中に OPPO `TX IN` −12.8 dBFS、Android 15 `RX` −23.1 dBFS、iPhone `RX` −16 dBFS を観測した。したがって両受信アプリのデコード段までは音声が届く。Android 16 の OS 通話音量は 3/15、出力先は本体スピーカー。Android 15 は後続採取で 3/5。iPhone のアプリ診断は出力音量 1.00、試験後ルートは Bluetooth と表示したが、送信中 UI は Speaker と表示した。ルートの変化時刻と実際の出力先は未確定。音量・ルートの影響を除外していない。Mac スピーカーの音を OPPO が近接して拾ったことだけは確認されている。

追加で Android 15 の `AudioFlinger` を有限35秒PTT中に確認。KOEONプロセス所有の再生トラック1本がOS上でactive、内部ミュートfalse、出力先speakerで、相手UIは `BUSY_REMOTE`。ただしOS再生トラックの中身が音声か無音かは、この情報では分からない。OS通話音量は3/5と表示された。先の3/15は別のAndroid 16エミュレーターの値であり、同一端末の変化ではない。Macの試験前音量も後続試験時には6へ変わっていたため、各試験で元の値へ戻した。端末の可聴再生を確認できたと扱わない。

## 残る作業
